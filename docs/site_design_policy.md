## 0. 前提 — 今回の刷新は「見た目の作り直し」ではない

現行サイトは **personal_branding_strategy v0.4（2026-05）の忠実な実装**である。

つまり **デザインだけ変えても「何の人か」は変わらない**。

**コピーと構成の変更が本体、ビジュアルはその結果**である。

## 2. 世界観 — 「工房」

> **作業台の上に、作ったものと測った数字が並んでいる。**

### 2.1 なぜ「工房」か

現行および Readdy 案は **漆黒 × ネオン × 光る抽象CG × 英語ヒーロー**＝「近寄りがたい先端テック」の記号。
これは掲げている思想と**逆**である。

> 技術は決して特別な人だけのものではなく、まちをより良くするための**共通言語**
> 「誰が作るか」ではなく、「**誰もが関われる仕組み**」をどう作るか
> — 千葉県庁講演 p68（本人の肉声）

| 主張 | 必要な記号 | 現状 |
|---|---|---|
| 作って、売って、測っている | **実物と数字** | 光る抽象CG（＝作っていないように見える） |
| 越境（講演 p38/44/45/54/62 で5回反復） | **領域を横断して並ぶグリッド** | 縦一列の履歴書 |
| 誰もが関われる／共通言語 | **明るい・読める・開いている** | 黒背景・低コントラスト |
| 枠の中では見えないニーズがある | **枠の外のものを見せる** | テンプレの枠そのもの |

補足理由:
- everyonelearns は「静謐・思想書」で確定済み。**あちらは思想、こちらは仕事**。見た目でも分ける
- ダーク＋ネオンは AI サイトビルダーのデフォルト。**「ビルダーで作った」と分かる見た目は、作る人のサイトとして致命的**

### 2.2 技術（XR / デジタルツイン / AI）の見せ方 ── 記号ではなく実物で

「工房」コンセプトは技術訴求と対立しない。**排除するのは技術そのものではなく、技術を演出する抽象CG**である。

| | 例 | 判定 |
|---|---|---|
| **記号としての技術** | 光る幾何学、パーティクル、ワイヤーフレーム、ネオングリッド | ❌ 作っていない人でも作れる見た目。**技術力がむしろ伝わらない** |
| **実物としての技術** | 点群・フォトグラメトリの実データ／3D都市モデルのビューア画面／BIM-CIMモデル／Unityエディタ画面／ヘッドセットを着けた現場／AIアバター対話画面 | ✅ **これがXR/DT/AIそのもの。**買い手に効くのはこちら |

→ 作業台の上に載っているのが点群と3Dモデルとヘッドセットなら、それは **XR/DTの工房**である。

**ヘッドラインには技術を置かない理由**（本人の肉声）:
> 技術とは「目的」ではなく「手段」（講演 p45）／ DXは目的ではなく手段（p47）
> ITは単なる効率化ツールではなく、「人の可能性を広げる力」（p45）

技術を主語にしたヘッドラインは本人の思想と矛盾する。**H1は思想、技術は手段の位置**に置く。
ただし「何屋か分からない」問題は実在するため、§5.1 の**技術タグ帯**で解決する。

### 2.3 やらないこと

- AI生成の抽象CG（光る幾何学・パーティクル・ワイヤーフレーム）を**一切使わない**
- 英語だけ格好よく、日本語は添え物、という構成にしない
- セクションを等価に7つ並べない（＝優先順位がない＝何の人か伝わらない）
- 空のセクションを置かない（載せるものが無ければセクションごと削除する）

## 4. 構成 — 7セクション等価から3層へ

```
現行: ホーム / About / Research / Career / Media&Links / Blog&Articles / Contact
       （全部同じ重さ）
  ↓
第1層  旗          ヒーロー（1文）＋ 一行の自己定義 ＋ 顔写真1枚
第2層  証拠        Works ＝ 主役。3〜5件。各件に「誰の何がどう変わったか」＋数字1行
第3層  背景と連絡  About（原体験・所属・研究）／ Career（畳む）／ Contact
```

**Works が主役。** 現行サイトには Works セクションが存在せず、Research History（論文・受賞）と
外部リンク集しかない。「作って売っている人」のサイトとして証拠がゼロの状態。

## 5. コピー（確定案）

### 5.1 ヒーロー（2026-08-03 確定）

**本サイトは名刺である。ヒーローにマニフェストを置かない。** H1は名前。

```
清水 啓太郎
Keitaro Shimizu

株式会社Play Life Studio 代表取締役 CEO

産業現場と行政に、XR・デジタルツイン・AIを実装しています。

[ XR / VR・AR ]  [ デジタルツイン / BIM・CIM・PLATEAU ]
[ 生成AI・対話エージェント ]  [ ゲーミフィケーション ]        ← 技術タグ帯
```

構成: **名前 → 肩書 → 説明1行（事実の記述）→ 技術タグ帯**
※ 現行の `hero.badge`（"XR × AI × HCI / 産業DXと民主化"）は技術タグ帯に統合して**廃止**する。

#### 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | **ヒーローに NVIDIA を出さない** | 個人サイトは所属明示可だが、前面に出すと「会社の看板」感が出る。**キャリアで触れる程度に留める** |
| 2 | **ヒーローから `Ph.D Candidate, The University of Tokyo (HCI)` を外す** | 研究を主軸にしない方針／在籍状態に依存させない。**学歴の事実として Education に1行残す**（「在学中」バッジは付けない） |
| 3 | **旗は everyonelearns へ移す** | 「誰が作るかではなく、誰もが関われる仕組みを。」は主語＝活動のサイトで機能する。個人の名刺サイトに置くと役割が食い合う |
| 4 | **人柄は About の原体験ブロックで出す** | ヒーローは静かに、About で語る。名刺の役割と矛盾しない |

#### 差し替え候補（メッセージ性を少し残したい場合）

説明1行を下記に置換するだけでよい。これが名刺として許容できる上限。

```
つくって、現場に置いて、使われるまで見ています。
```

## 7. 禁則（公開前チェック）

1. **NVIDIA表記** — 本サイトは所属レベルの明示のみ可（[CLAUDE.md](../../../CLAUDE.md) 例外規定）。
   **具体プロジェクト・顧客名・社内情報・未公開ロードマップには一切触れない**
2. **顧客名・案件名** — 許諾なしで出さない
3. **行政の内部情報** — 千葉県の意思決定プロセスは書かない（公務員守秘）
4. **数字を盛らない** — 実測値のみ。無ければ書かない
5. 公開前に `quality-reviewer`（LP品質チェック）と `critic` を通す

## 8. 実装・運用

- **ドメインは `keitaro-shimizu.com` を維持**（SEO・被リンク・OG資産を捨てない）

  接続できないなら **Readdy は案出しに留め、実装は本 React リポジトリに反映する**

- フッターに1行: 「思想と活動については everyonelearns へ」
